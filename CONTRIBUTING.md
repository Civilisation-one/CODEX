# Contributing to CODEX

CODEX documents change only through reviewed pull requests.

1. **Open an issue** naming the document ID (for example `CV1-PLATFORM-CODEX-001`), the section, and the problem or proposal.
2. **Make one focused change per branch.** Do not mix unrelated edits.
3. **Open a pull request** that states:
   - the evidence or reason for the change;
   - what it affects (other CODEX documents, code, contracts);
   - the document status after the change (`DRAFT`, `PROPOSED`, `ACCEPTED`, `SUPERSEDED` or `WITHDRAWN`).
4. **Review.** An authorised maintainer reviews and merges. Only the maintainer moves a document to `ACCEPTED`.
5. **History is kept.** Prior versions stay visible in the repository history; do not rewrite or force-push `main`.

Unresolved objections are recorded, not deleted (CV1-PLATFORM-CODEX-001 §7.4).

Proposals from people or agents outside the maintainer group are welcome as issues or pull requests. A proposal, however it is worded, does not grant authority over this repository or over Civilisation.One systems.
